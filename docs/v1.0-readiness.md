# v1.0 Readiness Notes

This repository now contains the Core-side foundation needed by the v1.0 PRD, but v1.0 is not complete until the required multi-repository deliverables are implemented and released.

## Implemented in Core

- Stable actor tuple semantics: `User -> UserMember -> Member -> Space`.
- Scope checks for `self`, `group`, `group_tree`, and `space`; normal Member use of `global` remains denied.
- Union grant evaluation with matched candidate trace output.
- Resource Registry tables and registry snapshots in authorization decisions and audit traces.
- Core HTTP API envelopes for system, authz, audit, spaces, groups, members, user-members, roles, permissions, resources, data preview, plugins, templates, and resource-types.
- Auth and Actor APIs with PBKDF2 password verification, opaque access/refresh tokens, revocable sessions, actor context lookup, and switch-member support.
- Plugin manifest validation, plugin metadata install/update, lifecycle status changes, settings definitions, and settings values.
- Seed metadata for required official plugins: Webhooks, API Keys, Notifications, and Moderation.
- Template catalog and installation record endpoints for `blank`, `internal-admin`, and `community-lite`.
- Data Console create, update, and soft-delete mutations for internal `resources` table mappings, with authz decisions returned alongside changed rows.
- Migration checksum verification and `plystractl doctor`.
- Health, readiness, version, and metrics endpoints.
- Static Console covering overview, system status, model browsers, permission inspection, audit detail, resource registry, Data Console, plugins, and templates.

## Remaining v1.0 Work

- Harden the static Console into a packaged production application with end-to-end tests and release artifacts.
- Move SDKs, plugin SDK, official plugins, templates, docs, console, and deploy assets into independently releasable repositories.
- Extend Data Console beyond the internal `resources` table mapping and add richer explain UI support for all row operations.
- Implement official plugin runtime behavior and separate plugin repositories, not only Core metadata.
- Add auth/session endpoints and actor-context APIs.
- Finish Go and Python SDKs, JS SDK tests, generated clients, examples, and package release metadata.
- Add production deployment guides for Docker Compose, systemd, Caddy, Nginx, external PostgreSQL, backup/restore, and upgrades.
- Add background worker runtime, structured logs, release tags, compatibility gates, and final v1.0 QA matrix.
